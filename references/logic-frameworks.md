## 一、MECE校验清单

**MECE = Mutually Exclusive, Collectively Exhaustive（相互独立，完全穷尽）**

### 校验步骤

```
1. 画出当前分类方案
2. 独立性测试：任意两个分类之间，是否有一个元素可以同时归入两类？
   → 有 = 交叉 → 需要调整分类维度或合并
3. 穷尽性测试：所有分类加总，是否等于全集？有没有遗漏的情况？
   → 有遗漏 = 不全 → 补充缺失维度
4. 维度统一测试：所有分类是否在同一个维度上切分？
   → 混用维度 = 混乱 → 选定单一切分标准
```

### 常见MECE切分维度

| 切分维度 | 举例 |
|---------|------|
| 时间 | 短期/中期/长期、过去/现在/未来、Q1/Q2/Q3/Q4 |
| 空间/结构 | 线上/线下、国内/海外、前端/后端/数据层 |
| 流程 | 获客→转化→留存→变现、需求→设计→开发→测试→上线 |
| 主体 | 用户/商家/平台、内部/外部、管理层/执行层 |
| 性质 | 定量/定性、可控/不可控、直接/间接 |
| 正反 | 优势/劣势、机会/威胁、支持/反对 |

### MECE违规常见模式

| 违规类型 | 示例 | 修复 |
|---------|------|------|
| 子集关系当并列 | "用户体验"和"界面设计" | 界面设计归入用户体验下一层 |
| 维度混用 | "年龄段"和"消费水平"并列 | 选一个维度，另一个做交叉分析 |
| 太笼统 | "其他"占比>30% | "其他"太大说明分类不够细 |

## 二、三种逻辑顺序选择指南

| 顺序 | 适用场景 | 判断标准 | 举例 |
|------|---------|---------|------|
| **时间/步骤** | 描述过程/计划 | 各项之间有先后依赖关系 | 项目规划、操作手册、历程回顾 |
| **空间/结构** | 描述组成/拆解 | 各项是整体的不同部分 | 组织架构、产品模块、市场区域 |
| **程度/重要性** | 描述评价/排序 | 各项独立但有优先级 | 问题排序、方案对比、风险评估 |

### 选择流程

```
Q1: 这些要点之间有先后顺序吗？
  → Yes → 时间/步骤顺序
  → No → Q2

Q2: 这些要点是某个整体的组成部分吗？
  → Yes → 空间/结构顺序
  → No → Q3

Q3: 这些要点需要排优先级吗？
  → Yes → 程度/重要性顺序
  → 都不是 → 检查是否需要重新分组
```

## 三、逻辑树模板

### A. 问题诊断型逻辑树

```
问题是什么？
├── 是否真的有问题？（问题界定）
│   ├── R1（现状）是什么？
│   └── R2（期望）是什么？
│       └── Gap = R2 - R1
├── 问题在哪里？（问题定位）
│   ├── 维度1拆解
│   ├── 维度2拆解
│   └── 维度3拆解
├── 为什么会这样？（原因分析）
│   ├── 根因1
│   ├── 根因2
│   └── 根因3
└── 怎么解决？（方案制定）
    ├── 方案A（优劣对比）
    ├── 方案B（优劣对比）
    └── 推荐方案 + 理由
```

### B. 方案选择型逻辑树

```
目标是什么？
├── 方案一
│   ├── 优势
│   ├── 劣势
│   ├── 成本
│   └── 风险
├── 方案二
│   ├── 优势
│   ├── 劣势
│   ├── 成本
│   └── 风险
└── 推荐结论
    ├── 选哪个？
    ├── 为什么？（核心判断依据）
    └── 怎么执行？（下一步行动）
```

## 四、演绎vs归纳判断流程

### 演绎推理（自上而下）

```
结构：大前提 + 小前提 → 结论
特征：从一般到个别，结论必然成立（如果前提为真）
风险：大前提不成立则整个推理崩塌

示例：
  大前提：所有超过预算20%的项目需要VP审批
  小前提：本项目超出预算25%
  结论：本项目需要VP审批
```

### 归纳推理（自下而上）

```
结构：事实1 + 事实2 + 事实3 → 总结/规律
特征：从个别到一般，结论是可能性（非必然）
风险：样本不足或有反例则结论不成立

示例：
  事实1：A客户因响应慢流失
  事实2：B客户因响应慢投诉
  事实3：C客户因响应慢降级
  归纳：响应速度是客户流失的关键因子
```

### 判断流程

```
Q: 是先有结论再找证据，还是先有证据再提炼结论？
  → 先结论后证据 = 演绎（验证型，确保前提成立）
  → 先证据后结论 = 归纳（发现型，确保样本充分）

Q: 论证中的"因为"在哪里？
  → "因为"引出普遍原则 = 演绎
  → "因为"引出多个具体事例 = 归纳
```

## 五、经典框架速查表

> 金字塔是思考的骨架，框架是常见骨架的模板。选对框架=省去从零搭建的时间。

| 框架 | 用途 | MECE维度 |
|------|------|---------|
| SWOT | 内外环境分析 | 内/外 × 正/负 |
| 3C | 战略分析 | 公司/客户/竞对 |
| 4P | 营销组合 | 产品/价格/渠道/推广 |
| 5W1H | 问题定义 | Who/What/When/Where/Why/How |
| PEST | 宏观环境 | 政治/经济/社会/技术 |
| 价值链 | 业务拆解 | 研发→采购→生产→营销→销售→服务 |
| 漏斗模型 | 转化分析 | 曝光→点击→转化→留存→复购 |
| 2×2矩阵 | 优先级判断 | 重要/不重要 × 紧急/不紧急 |
| 利益相关方 | 协作分析 | 高影响力/低影响力 × 高利益/低利益 |
| OKR结构 | 目标拆解 | Objective → Key Results → Initiatives |

### 框架选择指南

```
我要分析什么？
├── 外部环境 → PEST / 行业五力
├── 竞争格局 → 3C / SWOT
├── 业务流程 → 价值链 / 漏斗模型
├── 具体问题 → 5W1H / 逻辑树
├── 决策排序 → 2×2矩阵 / 评分卡
└── 目标规划 → OKR结构 / 逻辑树(方案型)
```

> 💡 本表仅收录金字塔构建中高频使用的核心框架，更多框架可参考商业分析经典模型。
