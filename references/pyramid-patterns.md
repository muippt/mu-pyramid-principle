# 金字塔构建模板

> 两条路径 + 四种序言变体，覆盖所有构建场景。

---

## 一、自上而下构建法

**适用场景**：已有明确观点/结论，需要组织论证结构。

### 步骤

```
Step 1: 提炼中心论点
  → 问自己：我最想让对方记住的一句话是什么？
  → 必须是完整判断句（主+谓+宾+判断）
  → ❌ "关于数字化转型" / ✅ "我们必须在Q3前完成数字化转型，否则将失去20%市场份额"

Step 2: 设想受众疑问
  → 站在读者角度：看到你的结论，他会问什么？
  → 常见疑问模式：为什么？怎么做？凭什么？有什么好处？有什么风险？

Step 3: 用3-5个子论点回答疑问
  → 每个子论点回答一个核心疑问
  → MECE校验：子论点之间不重叠、不遗漏
  → 选择逻辑顺序：时间/结构/重要性

Step 4: 为每个子论点匹配论据+数据
  → 论据：为什么这个子论点成立？
  → 数据：有什么事实/数字佐证？
  → 逻辑三要素校验：观点-论据-数据缺一不可

Step 5: 撰写SCQA序言（见下方变体）

Step 6: 整合输出，通读验证
  → "以上统下"测试：删掉上一层，下面的内容能否独立推出上层？
  → 层级检查：不超过4层
```

### 示例：季度述职

```
🔺 本季度超额完成目标，团队已具备承接更大业务的能力
├── 业务结果：GMV达成率115%，超目标15个百分点
│   ├── 新客转化率提升8%（优化了入口链路）
│   └── 客单价提升12%（推出组合套餐策略）
├── 能力建设：搭建了XX系统，人效提升30%
│   ├── 自动化流程从3个扩展到7个
│   └── 人均处理订单从200/天提升到260/天
└── 团队发展：核心岗位填充率100%，梯队初步成型
    ├── 招入2名高级工程师，补齐技术短板
    └── 3名基层管理者完成管理培训，可独立带小组
```

## 二、自下而上构建法

**适用场景**：有大量散乱素材/想法，需要整理出结构。

### 步骤

```
Step 1: 罗列所有要点
  → 不加筛选，把想说的全部写下来
  → 一个要点一行，不管顺序

Step 2: 寻找关系，归类分组
  → 哪些要点在说同一件事？
  → 用什么维度分最自然？（时间/空间/重要性）
  → MECE检查：有没有遗漏？有没有重叠？

Step 3: 为每组提炼一句话（子论点）
  → 这组要点合在一起说明了什么？
  → 必须是判断句，不是标签

Step 4: 从子论点中提炼总论点
  → 所有子论点加在一起，证明了什么？
  → 这就是你的中心论点

Step 5: 验证"以上统下"
  → 从总论点出发，能否推出每个子论点？
  → 从子论点出发，能否支撑总论点？
  → 不能的就调整层级或删除

Step 6: 补充SCQA序言
```

### 示例：从散乱要点到金字塔

**原始要点（打散状态）**：
- 客户投诉增加了30%
- 新来的客服经验不足
- 系统响应速度慢了
- 工单积压超过500件
- 老客服离职了3个
- 排班不合理导致高峰期人手不够

**归类分组**：
- 人的问题：老客服离职3个、新客服经验不足、排班不合理
- 系统问题：系统响应速度慢
- 结果表现：客户投诉+30%、工单积压500+

**提炼金字塔**：
```
🔺 客服体验恶化的根因是人员流失+系统瓶颈，建议双线并行修复
├── 人员缺口是核心矛盾（3人离职+新人不熟+排班失衡）
├── 系统响应慢放大了人效问题（工单积压500+的直接原因）
└── 不修复将持续恶化（投诉已+30%，趋势未见拐点）
```

## 三、SCQA序言四变体

### 1. 标准式（正式汇报）

```
S（背景）：公司正在推进数字化转型，目标是年底前上线新系统。
C（冲突）：当前进度落后计划3周，且核心开发人员即将轮岗。
Q（疑问）：如何确保项目按期交付？
A（回答）：建议采取三个措施——增补人力/砍非核心需求/引入外部资源。
```

### 2. 行动式（紧急决策，结论前置）

```
A（回答）：我们需要立即暂停X项目，将资源转移到Y项目。
S（背景）：X项目已投入6个月，但市场环境发生了根本变化。
C（冲突）：继续投入X将浪费资源，而Y有明确的营收窗口即将关闭。
Q（疑问）：具体如何执行转移？（下面展开）
```

### 3. 冲突式（说服对方，痛点开场）

```
C（冲突）：我们的客户续费率已经连续3个季度下降，再不干预Q4将跌破60%。
S（背景）：过去我们靠产品力自然续费，但竞品在客户成功上投入了3倍人力。
Q（疑问）：如何扭转续费率下滑趋势？
A（回答）：建立客户成功体系，分三步走。
```

### 4. 提议式（方案推荐，问题导向）

```
Q（疑问）：如何用有限预算实现用户增长翻倍？
S（背景）：当前获客成本180元/人，年预算2000万，按现有效率只能新增11万用户。
C（冲突）：目标是22万新增用户，gap = 11万，现有渠道已接近天花板。
A（回答）：开辟私域裂变渠道（获客成本预估60元），可覆盖gap。
```

## 四、「论证类比」四字诀（速记工具）

> 来源：《结构思考力》第三章。把金字塔四原则口诀化、工具化，方便快速校验。

| 字 | 对应原则 | 口诀 | 操作要点 |
|----|---------|------|---------|
| **论** | 结论先行 | 一次表达，一个主题，说在开头 | 开口第一句必须是结论判断句，不是"关于XX" |
| **证** | 以上统下 | 结论在上，理由在下，相互联系 | 每个结论配2-5条理由，理由之间有逻辑联系 |
| **类** | 归类分组 | 合理分类，不重不漏，简化问题 | MECE原则，找自然维度（人/事/物、问题/方案） |
| **比** | 逻辑递进 | 逻辑排列，根据逻辑，明确顺序 | 组内按时间/重要性/结构排序 |

### 四字诀快速校验法

拿到一段表达，按顺序检查：
1. **论**：第一句话是结论吗？→ 不是则前置
2. **证**：结论有理由支撑吗？→ 没有则补论据
3. **类**：理由分组清晰吗？不重不漏？→ 重叠则合并，遗漏则补充
4. **比**：每组内的顺序有逻辑吗？→ 无序则按重要性/时间排列

### 示例：秘书汇报改写

**诊断（四字诀逐项）**：
- ❌ 论：开篇无结论，用"刘经理来电话说…"叙事开头
- ❌ 证：理由散落在对话转播中，未与结论绑定
- ❌ 类：人员信息和会议室信息混在一起
- ❌ 比：按"谁先打电话"排序，而非按重要性排序

**改写后**：
> 建议将会议改到周五10:00（**论**）。原因有二：一是参会人员时间合适——王总周五已回、刘经理今天无法参会、小张时间灵活（**证+类：人员维度**）；二是会议室周五空闲（**证+类：资源维度**）。人员按职务重要性排序（**比**）。

## 五、金字塔可视化输出规范

### 标准格式

```
🔺 [中心论点]
├── [子论点1]
│   ├── [论据/数据]
│   └── [论据/数据]
├── [子论点2]
│   ├── [论据/数据]
│   └── [论据/数据]
└── [子论点3]
    ├── [论据/数据]
    └── [论据/数据]
```

### 格式规则

1. 顶层用 🔺 标识
2. 树状用 `├──` 和 `└──` 连接
3. 缩进用 `│   ` 对齐
4. 每个节点是完整的句子，不是关键词
5. 最多4层（含顶层）
6. 每层分支3-7个（超过7个需要再分组）

### 简化格式（短文本/消息场景）

```
🔺 结论：...
  ∟ 论据1：...
  ∟ 论据2：...
  ∟ 论据3：...
```
